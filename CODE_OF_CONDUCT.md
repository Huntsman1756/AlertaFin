# Código de conducta

## Propósito

AlertaFin es un proyecto abierto de software e investigación reproducible. La participación debe mantener un entorno profesional, seguro y centrado en la evidencia, tanto para contribuciones técnicas como para discusiones sobre fuentes regulatorias.

## Comportamiento esperado

Se espera de quienes participen:

- tratar a otras personas con respeto y buena fe;
- discutir hechos, código y evidencia sin ataques personales;
- aceptar revisión técnica y desacuerdo razonado;
- distinguir observaciones, inferencias y opiniones;
- respetar las reglas de privacidad, provenance y evidencia congelada del repositorio;
- corregir errores de forma trazable, sin reescribir resultados históricos para mejorar su apariencia.

## Comportamiento no aceptado

No se acepta:

- acoso, amenazas, intimidación o lenguaje discriminatorio;
- insultos, ataques personales o provocación deliberada;
- publicación de datos personales innecesarios, credenciales, secretos o información obtenida de forma privada;
- spam, autopromoción ajena al proyecto o manipulación coordinada de issues/PR;
- falsificación, ocultación o alteración engañosa de evidencia, resultados o provenance;
- cualquier conducta que dificulte de forma deliberada la revisión técnica o la participación segura de otras personas.

## Alcance

Este código se aplica a issues, pull requests, revisiones, comentarios y demás espacios públicos vinculados al repositorio, así como a interacciones privadas relacionadas directamente con su mantenimiento.

## Reporte de incidentes

Para problemas de moderación no sensibles puede abrirse un issue con el contexto mínimo necesario.

Si el reporte contiene acoso, datos personales u otros detalles sensibles, no publiques esos detalles en un issue. Usa las herramientas de reporte de abuso de GitHub o un canal privado disponible del mantenedor. Si no existe un canal privado visible, abre únicamente un issue mínimo titulado `[conduct] private contact requested` y continúa el intercambio de detalles fuera del espacio público.

Los reportes de vulnerabilidades de seguridad siguen el proceso específico de `SECURITY.md`.

## Aplicación

El mantenedor puede editar o retirar contenido, cerrar conversaciones, rechazar contribuciones o limitar temporal o permanentemente la participación cuando sea necesario para aplicar estas reglas. Las decisiones deben basarse en la conducta observada y su impacto sobre el proyecto, no en desacuerdos técnicos de buena fe.

Este documento puede evolucionar mediante el mismo flujo de pull request y revisión que el resto de la gobernanza del repositorio.
